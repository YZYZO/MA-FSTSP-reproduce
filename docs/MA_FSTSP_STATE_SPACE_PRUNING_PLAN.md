# MA-FSTSP 状态空间剪枝顺序实施文档

## 1. 文档目的

本文档面向论文 **Optimization of Multi-Agent Flying Sidekick Traveling Salesman Problem over Road Networks** 及当前仓库中的实现，给出一套可按顺序执行的状态空间剪枝方案。

覆盖范围同时包括：

1. 第二阶段 Set-TSP 的 MILP 变量空间、候选端点空间和分支定界空间；
2. 第三阶段动态规划的客户块、发射点、回收点、中间点和 `VALUE` 状态空间。

本阶段只编写实施文档，不修改 `src/fstsp.py` 等生产代码。后续实施时，每一项剪枝都应独立提交、独立测试、独立统计，禁止一次混入多项优化，否则出现结果差异时难以判断来源。

## 2. 当前代码中的状态空间

### 2.1 第二阶段 Set-TSP

入口位于：

- `src/fstsp.py::get_seq`
- `src/fstsp.py::set_tsp`

当前主要变量为：

| 变量 | 当前代码 | 含义 | 规模 |
|---|---|---|---|
| `select[i,j]` | `set_tsp` 第 259 行附近 | 集合 `i` 后是否访问集合 `j` | \(O(n^2)\) |
| `flow[i,j]` | 第 263 行附近 | Gavish-Graves 连通流 | \(O(n^2)\) |
| `internal[i][a][b]` | 第 271 行附近 | 在集合 `i` 中选择进入端点 `a` 和离开端点 `b` | \(\sum_i |S_i|^2\) |
| `external[i][j][a][b]` | 第 274 行附近 | 从集合 `i` 的端点 `a` 到集合 `j` 的端点 `b` | \((\sum_i |S_i|)^2\) |

其中 `external` 是主要变量来源。当前实现连 `i == j` 的变量也全部创建，然后再通过 `select[i,i] == 0` 间接固定为零。

### 2.2 第三阶段动态规划

入口位于：

- `src/fstsp.py::local_search_multi_drone_appr`

为便于证明，本文使用以下逻辑记号：

- \(R(c)\)：客户 \(c\) 的候选发射/回收节点区域，对应 `self.regions[c]`；
- \(A_{s,t}(v,u)\)：从共同发射点 \(u\) 出发，同时处理从第 \(s\) 个客户开始的 \(t\) 个连续客户，最后在 \(v\) 回收的时间，对应 `appr`；
- \(F_s(v)\)：已经处理前 \(s\) 个客户并停在节点 \(v\) 时的最优时间，对应 `value`。

当前主要空间为：

1. `value`：为每一层和路网中的每一个节点创建状态；
2. `prefix`：为每一个 `value` 状态复制完整卡车/无人机路线；
3. `appr`：为每个客户、每个无人机数量、每对发射/回收点创建状态；
4. `tour`：为每个 `appr` 状态复制完整局部路线；
5. 每次转移枚举上一客户区域中的全部 `_mid`。

当前 `value` 和 `prefix` 的创建位置约为第 389-398 行，而真正参与转移的节点主要来自相应客户的 `self.regions`。因此存在大量从初始化开始就永远为 `inf` 的结构性不可达状态。

## 3. 安全性等级

后续实现必须在代码、实验结果和论文描述中明确区分以下等级。

### 3.1 A 级：严格安全剪枝

在当前三阶段算法、当前客户访问顺序和当前数值模型不变的条件下，可以证明：

- 被删除状态不可能属于严格更优解；
- 剪枝前后最优目标值一致；
- 若只要求保留一个最优解，允许删除与当前上界相等的替代解；
- 若要求保留全部最优解，判断条件必须使用严格不等式。

本文优先级 P1-P9 均按 A 级剪枝设计。

### 3.2 B 级：条件安全剪枝

只有在额外假设成立时才安全，例如：

- 路网无向；
- 候选区域互不重叠；
- 卡车在访问集合期间不能离开集合；
- 已完整预计算区域内部闭包。

条件没有在程序中显式检查时，不能宣称为严格剪枝。

### 3.3 C 级：有损启发式裁剪

可能删除当前模型中的最优解，只能通过质量—时间实验评价，例如：

- 每个集合只保留最近的若干外部集合；
- Beam Search；
- 每层只保留固定数量的 DP 状态；
- 重叠节点只分配给最近客户；
- 未做内部闭包就只保留区域边界节点。

## 4. 实施前的统一约定（P0）

P0 本身不是剪枝，但必须在任何剪枝之前完成。

### 4.1 固定比较对象

每项剪枝比较的是“当前代码所定义的三阶段算法”，不是原始 MA-FSTSP 全局最优解。

特别需要区分：

1. Phase 2 的 Set-TSP 本身是客户顺序启发式；
2. Phase 3 在固定客户顺序下，又使用了同时发射无人机的近似；
3. 因此“严格安全”表示不改变对应阶段当前数学模型的最优值，不表示恢复 MA-FSTSP 的全局最优性。

### 4.2 统一候选区域边界

当前代码中存在 `< r/2` 与 `<= r/2` 的差别。后续证明应统一采用：

\[
d_{\mathrm{dr}}(v,c) \le r/2+\varepsilon_d
\]

其中 \(\varepsilon_d\) 是固定距离容差。

不能把浮点误差导致的等号节点删除包装成“剪枝收益”。

### 4.3 固定随机性和求解器设置

使用当前已有的：

- `gurobi_threads=1`
- 固定 `gurobi_seed`
- 固定实例种子

比较时至少记录：

- 最优成本；
- 可行性；
- Set-TSP 变量数和约束数；
- Gurobi 节点数、运行时间、MIP Gap；
- DP 各类候选状态数、实际展开状态数和剪枝数；
- 卡车距离查询数、无人机距离查询数；
- 峰值内存。

### 4.4 每项剪枝使用独立测试文件

遵循项目要求，不复用旧测试文件承载新的剪枝验证。每个优先级对应的建议测试文件会在后文列出。

# 6. P1：Set-TSP 结构性零变量剪枝

## 6.1 当前冗余

`set_tsp` 当前创建：

1. `select[i,i]`，随后约束其等于 0；
2. `flow[i,i]`，随后约束其等于 0；
3. 所有 `external[i][i][a][b]`，但其和等于 `select[i,i] == 0`；
4. 仓库集合只有一个节点时，唯一的 `internal` 变量被约束为 1。

这些变量的取值在模型创建前就已经完全确定。

## 6.2 剪枝规则

只为以下索引创建变量：

\[
\mathcal A_{\mathrm{set}}=\{(i,j)\mid i\ne j\}
\]

\[
\mathcal A_{\mathrm{external}}
=\{(i,j,a,b)\mid i\ne j,\ a\in S_i,\ b\in S_j\}
\]

对单节点仓库集合，将唯一 `internal` 变量直接代入为常数 1。

## 6.3 严格证明

由现有约束：

\[
select_{i,i}=0
\]

以及：

\[
\sum_{a\in S_i}\sum_{b\in S_i}
external_{i,i,a,b}=select_{i,i}
\]

全部 `external` 是非负二进制变量，因此：

\[
external_{i,i,a,b}=0,\quad\forall a,b\in S_i
\]

同理，`flow[i,i] == 0` 已被现有约束显式固定。

删除固定变量并在约束中用常数替代，得到的是原模型在固定变量后的投影。原模型的每个可行解与稀疏模型的可行解一一对应，目标函数也不变，因此最优目标值严格相同。

## 6.4 具体修改方式

修改 `src/fstsp.py::set_tsp`：

1. 把 `select` 从稠密 `addMVar((n,n))` 改为只包含 `i != j` 的稀疏索引；
2. 把 `flow` 改成相同集合弧索引；
3. `external` 只创建 `i != j` 的候选端点对；
4. 入度、出度、流平衡约束改为对稀疏索引求和；
5. 序列恢复时只枚举当前集合真实存在的外出弧；
6. 给变量设置稳定名称，便于 P8 将整数模型与 LP 松弛变量对应；
7. 增加以下指标：
   - `phase2_structural_variables_skipped`
   - `phase2_external_self_arc_variables_skipped`
   - `phase2_fixed_internal_variables`

建议后续新增纯函数或辅助模块 `src/pruning.py`，负责生成稀疏索引；所有函数均按项目要求添加中文函数说明和关键变量注释。

## 6.5 独立测试

新增：

`tests/test_set_tsp_structural_zero_pruning.py`

至少包含：

1. 2-5 个集合的人工小实例；
2. 稠密旧模型与稀疏新模型成本一致；
3. 恢复出的顺序均满足每个集合一入一出；
4. 稀疏模型中不存在 `i == j` 的外部变量；
5. 有向非对称距离下仍然一致；
6. 等成本多解时只比较目标值和可行性，不要求顺序完全相同。

## 6.6 验收条件

- 所有实例成本绝对误差不超过 `1e-7`；
- 稀疏模型变量数严格减少；
- 模型可行性不变；
- 不依赖 Gurobi Presolve 才能体现变量减少。

# 7. P2：DP 不可达状态、滚动层和父指针剪枝

## 7.1 当前冗余

当前代码为每一个 DP 层和每一个路网节点创建 `value` 与 `prefix`：

\[
O(n|V|)
\]

但实际转移只访问：

- 初始仓库；
- 当前客户对应的 \(R(c_i)\)；
- 最终仓库。

此外，`prefix` 和 `tour` 在每次更新时复制完整列表，导致一个状态的存储成本随路径长度增长。

## 7.2 剪枝规则

### 规则 1：只创建合法层的节点

对第 \(i\) 个客户：

- “移动到发射区域”的层只保存 \(R(c_i)\)；
- “完成该客户或客户块”的层只保存 \(R(c_i)\)；
- 初始层和结束层只保存仓库。

### 规则 2：数值层使用滚动窗口

由于一次转移最多回看 \(k\) 架无人机覆盖的客户块，只保留计算未来转移所需的最近若干数值层。

建议实现时不要直接假设窗口长度，而应根据转移索引：

`2 * i - 2 * j - 1`

推导所需最早层，并用断言检查被释放层不会再被访问。

### 规则 3：路线改为父指针

每个获胜状态只保存：

- 前一状态编号；
- 本次动作类型；
- 本次发射点、客户、回收点；
- 必要的中间回收点。

求解结束后从仓库终态反向恢复一次完整路线。

## 7.3 严格证明

### 不可达节点删除证明

现有转移循环只会向 \(R(c_i)\) 中的节点写入有限值。对不属于对应区域的节点：

1. 初始值为 \(+\infty\)；
2. 没有任何转移向其写入；
3. 后续转移也不读取这些节点。

因此这些状态在 DP 依赖图中的入度为零且不是初始状态，永远不可达。删除它们不改变任何有限状态的递推值。

### 滚动层证明

DP 是有向无环的分层图。若某一层的全部后继转移已经计算完成，且不存在任何未来转移索引指向该层，则该层不再影响终态。

删除这种层只删除已经完成传播的历史数值，不删除父指针，所以：

- 终态最优值不变；
- 最优路线仍可通过父指针恢复。

### 父指针证明

完整路线副本只用于最终重建，不参与目标值比较。每次状态更新时记录产生当前最优值的前驱及动作，与复制完整前缀具有相同的信息量。沿父指针回溯得到的动作序列与原复制方案对应，因此不改变最优值或可行性。

## 7.4 具体修改方式

修改 `src/fstsp.py::local_search_multi_drone_appr`：

1. 将 `value` 从“全图节点字典列表”改为按层的稀疏字典；
2. 将 `prefix` 替换为 `value_parent`；
3. 将 `tour` 替换为 `appr_parent`；
4. 数值层采用显式层编号加滚动字典，禁止复用索引后导致父指针混淆；
5. 终态确定后调用单独的 `_reconstruct_dp_solution`；
6. 增加断言：
   - 每个有限状态都在合法区域中；
   - 每个父指针指向更早层；
   - 回溯最终到达仓库初态；
7. 增加指标：
   - `phase3_dense_states_avoided`
   - `phase3_peak_live_value_states`
   - `phase3_parent_records`
   - `phase3_route_copy_operations`

## 7.5 独立测试

新增：

`tests/test_dp_sparse_state_and_parent_pruning.py`

至少验证：

1. 旧版完整存储与新版稀疏存储目标值一致；
2. 重建路线的客户覆盖、航程和同步约束合法；
3. 0、1、多架无人机场景；
4. 单客户、客户数少于无人机数、客户数大于无人机数；
5. 有向非对称卡车距离；
6. 多个前驱等成本时仍能终止回溯；
7. 峰值状态数小于旧版理论状态数。

## 7.6 验收条件

- 成本一致；
- 路线可行；
- 不再创建 \(O(n|V|)\) 的 `value/prefix`；
- 路线列表只在最终回溯时构造一次。

# 8. P3：Set-TSP 可行上界与成本下界剪枝

这一项是第二阶段最推荐的成本型剪枝。它不依赖 LP reduced cost，容易解释，也具有明显的数据库“先算下界、再避免展开候选”的特点。

## 8.1 先构造可行上界

必须先得到一个 Set-TSP 可行解成本 \(UB\)。

建议两级实现：

### 一级上界

固定任意合法集合顺序，例如：

- Phase 1 组内客户的 LKH/TSP 顺序；
- 当前客户列表顺序。

每个集合选择一个合法进入/离开端点，构造完整环。即使成本较差，只要满足 Set-TSP 约束，就是合法上界。

### 二级上界

固定集合顺序后，对每个集合的进入/离开端点做分层最短路或动态规划，得到该顺序下最优端点组合。这仍是 Set-TSP 的可行解，通常比随意选择端点更紧。

该解还可以作为 Gurobi MIP Start。

## 8.2 基础下界

记集合内部最小服务成本：

\[
\alpha_i=\min_{a,b\in S_i}g_i(a,b)
\]

记两个不同集合之间的最小外部成本：

\[
m_{ij}=\min_{a\in S_i,b\in S_j}d_{\mathrm{tr}}(a,b),\quad i\ne j
\]

在集合层构造指派松弛：

\[
\min\sum_{i\ne j}m_{ij}x_{ij}
\]

满足每个集合恰好一条入弧和一条出弧，但不加消除子环约束。记其最优值为 \(LB_{\mathrm{assign}}\)。

基础下界为：

\[
LB_0=\sum_i\alpha_i+LB_{\mathrm{assign}}
\]

## 8.3 内部变量剪枝

若强制：

\[
internal_{i,a,b}=1
\]

则一个有效下界为：

\[
LB^{\mathrm{int}}_{i,a,b}
=g_i(a,b)+\sum_{h\ne i}\alpha_h+LB_{\mathrm{assign}}
\]

如果：

\[
LB^{\mathrm{int}}_{i,a,b}>UB
\]

则删除该内部变量。

若只要求保留一个最优解，可将 `>` 改为 `>= UB-\varepsilon`；若希望保留全部等价最优解，应使用严格大于。

## 8.4 外部端点变量剪枝

对候选：

\[
external_{i,j,a,b}=1
\]

固定集合弧 \(i\to j\)，并在集合指派问题中删除对应的行、列，求其余集合弧的指派松弛值：

\[
LB^{\mathrm{rem}}_{i\to j}
\]

则：

\[
LB^{\mathrm{ext}}_{i,j,a,b}
=\sum_h\alpha_h+d_{\mathrm{tr}}(a,b)
+LB^{\mathrm{rem}}_{i\to j}
\]

如果该值大于上界，则删除该外部端点变量。

若一个集合弧 \(i\to j\) 的全部端点变量都被删除，则：

\[
select_{i,j}=0
\]

也可以直接删除对应 `select` 和 `flow` 变量。

## 8.5 严格证明

Set-TSP 的任意可行解必须：

1. 对每个集合选择一个内部端点对；
2. 对每个集合选择一条入集合弧和一条出集合弧；
3. 满足单环约束和端点连续约束。

上述下界进行了两种放松：

1. 每个未固定集合只取独立的最小内部成本，忽略端点连续性；
2. 集合层只保留一入一出，删除单环约束，允许多个子环。

删除约束只会扩大可行域，因此松弛最优值不会高于任何满足原约束的解。

如果包含某个候选变量的所有原模型可行解，其下界已经高于当前可行上界，那么该候选不可能出现在更优解中，删除严格安全。

## 8.6 具体修改方式

建议在新辅助模块中实现：

- `_build_set_tsp_incumbent`
- `_compute_internal_minima`
- `_compute_set_assignment_lower_bound`
- `_compute_forced_arc_assignment_bound`
- `_filter_variables_by_bound`

在 `get_seq` 已经生成 `set_distance` 和 `distance` 后、调用 `set_tsp` 前执行。

数据流应为：

1. 原始候选集合；
2. 构造可行上界；
3. 计算内部最小值与集合指派下界；
4. 得到允许的 `internal` 和 `external` 稀疏索引；
5. `set_tsp` 只为保留索引创建变量；
6. 把上界解写入 MIP Start；

# 9. P4：DP 共同发射点位图交集剪枝

## 9.1 当前规则不足

当前代码在扩展连续客户块时主要检查：

\[
d_{\mathrm{dr}}(c_s,c_t)<2r
\]

该条件只是非常弱的必要条件。即使首尾客户距离小于 \(2r\)，离散路网中也可能不存在一个发射点能同时覆盖整个客户块。

## 9.2 精确剪枝规则

预计算：

\[
D(c)=\{u\in V\mid d_{\mathrm{dr}}(u,c)\le r+\varepsilon_d\}
\]

对于从客户 \(c_s\) 开始、长度为 \(t\) 的连续块：

\[
B_{s,t}=(c_s,c_{s+1},\ldots,c_{s+t-1})
\]

其共同发射点候选为：

\[
L_{s,t}=R(c_s)\cap\bigcap_{q=s}^{s+t-1}D(c_q)
\]

如果：

\[
L_{s,t}=\varnothing
\]

则整个客户块对应的全部 `appr/TIME` 状态都可以删除。

如果交集非空，也只需要为：

\[
u\in L_{s,t}
\]

创建 `appr` 状态，不再枚举 \(R(c_s)\) 中的其他节点。

## 9.3 严格证明

考虑当前代码中任意可行的同时发射客户块。

共同发射点为 \(u\)。对于块中每个由无人机服务的客户 \(c_q\)，存在回收点 \(v_q\)，并满足：

\[
d_{\mathrm{dr}}(u,c_q)+d_{\mathrm{dr}}(c_q,v_q)\le r
\]

因为距离非负：

\[
d_{\mathrm{dr}}(u,c_q)\le r
\]

对块首客户，即使当前基础递推选择卡车服务，代码仍要求共同起点：

\[
u\in R(c_s)
\]

而 \(R(c_s)\) 的半径不超过 \(r/2\)，所以首客户同样满足 \(d_{\mathrm{dr}}(u,c_s)\le r\)。

因此任何可行客户块的共同发射点必然属于 \(L_{s,t}\)。若交集为空，则不存在可行共同发射点，删除整个块严格安全。

## 9.4 位图实现方式

建议先使用不增加第三方依赖的整数位图：

1. 为图节点建立稳定的稠密编号 `node -> bit_index`；
2. 每个 \(D(c)\) 和 \(R(c)\) 使用 Python 整数或紧凑位数组；
3. 固定起点 `s`，块长度每增加 1，只做一次按位 AND；
4. 一旦交集为空，更长的同起点客户块也一定为空，可以立即停止扩展。

单调性为：

\[
L_{s,t+1}=L_{s,t}\cap D(c_{s+t})
\subseteq L_{s,t}
\]

所以：

\[
L_{s,t}=\varnothing\Rightarrow
L_{s,t'}=\varnothing,\quad\forall t'>t
\]

这允许同时剪掉同一起点下全部更长客户块。

## 9.5 当前样本统计

在本地 4,333 节点 Manhattan 图、固定随机种子的 50 客户只读样本中：

- 半径 \(r/2\) 原始区域平均约 136.1 个节点；
- 3 客户块中约 15.9% 的共同发射点交集为空；
- 4 客户块中约 38.1% 的共同发射点交集为空；
- 现有首尾距离规则分别漏掉 4 个和 12 个不可行块。

该统计只用于说明潜力，不能替代正式 100 实例实验。

## 9.6 具体修改方式

- `local_search_multi_drone_appr`：在创建 `appr` 之前滚动计算客户块交集；

# 10. P5：DP 中间回收点与前驱状态支配剪枝

## 10.1 中间回收点支配

对固定：

- 共同发射点 \(u\)；
- 当前客户；
- 当前最终回收点 \(v\)；

递推具有形式：

\[
A_t(v,u)=
\min_w
\max\{
A_{t-1}(w,u)+d_{\mathrm{tr}}(w,v),
f_t(u,v)
\}
\]

其中 \(f_t(u,v)\) 与中间点 \(w\) 无关。

如果两个中间点 \(w_1,w_2\) 满足：

\[
A_{t-1}(w_1,u)\le A_{t-1}(w_2,u)
\]

且：

\[
d_{\mathrm{tr}}(w_1,v)\le d_{\mathrm{tr}}(w_2,v)
\]

则 \(w_2\) 可被删除。

### 严格证明

两式相加得到：

\[
A_{t-1}(w_1,u)+d_{\mathrm{tr}}(w_1,v)
\le
A_{t-1}(w_2,u)+d_{\mathrm{tr}}(w_2,v)
\]

函数：

\[
x\mapsto\max\{x,f_t(u,v)\}
\]

关于 \(x\) 单调不减，因此通过 \(w_1\) 的转移值不大于通过 \(w_2\) 的值。删除 \(w_2\) 不可能使该状态最优值增大。

## 10.2 跨全部目标节点的支配

为了让预处理本身产生收益，优先使用更强的“对整个下一区域支配”。

对固定发射点 \(u\)，如果：

\[
A_{t-1}(w_1,u)\le A_{t-1}(w_2,u)
\]

并且对下一客户区域的全部 \(v\)：

\[
d_{\mathrm{tr}}(w_1,v)\le d_{\mathrm{tr}}(w_2,v)
\]

则 \(w_2\) 对该次客户块扩展中的所有最终回收点都被支配，可以在进入 `for node in ...` 前删除。

## 10.3 `VALUE` 前驱状态支配

对完成前 \(s\) 个客户后的两个状态 \(q_1,q_2\)，下一步必须先移动到下一客户区域中的某个节点 \(x\)。

若对所有 \(x\in R(c_{s+1})\)：

\[
F_s(q_1)+d_{\mathrm{tr}}(q_1,x)
\le
F_s(q_2)+d_{\mathrm{tr}}(q_2,x)
\]

则状态 \(q_2\) 可以删除。

### 严格证明

从状态 \(q\) 出发的任何后续策略，首先选择一个下一事件节点 \(x\)。到达 \(x\) 后，后续状态只记录：

- 已处理客户数量；
- 当前节点 \(x\)；

不再依赖之前是从 \(q_1\) 还是 \(q_2\) 到达。

对于使用 \(q_2\to x\) 的任意完整方案，用 \(q_1\to x\) 替换其前缀不会增加成本，后缀完全保持不变。因此 \(q_2\) 不可能是严格更优完整方案的必要状态。

## 10.4 具体修改方式

在 `src/pruning.py` 中建议提供纯函数：

- `find_dominated_midpoints`
- `find_dominated_value_states`

在 `local_search_multi_drone_appr` 中：

1. 每次进入 `_mid` 循环前形成候选中间点列表；
2. 先删除 `inf` 状态；
3. 对下一目标区域做向量支配检查；
4. 只枚举保留下来的中间点；
5. 相等候选使用稳定编号保留一个代表，避免两个状态互相删除；
6. 若支配检查耗时超过节省的距离查询，应允许通过选项关闭。

可选加速：

- 对候选按 `A` 值排序；
- 维护距离向量的 Skyline；
- 使用 NumPy 块比较；
- 区域较小时直接两两比较，区域较大时才启用索引。

- `phase3_midpoints_dominated`

- `phase3_value_states_dominated`
- `phase3_dominance_seconds`

# 11. P6：DP 上界与剩余有序区域下界剪枝

## 11.1 初始可行上界

对固定客户访问顺序，卡车依次直接访问全部客户并返回仓库是一条可行解：

\[
UB_{\mathrm{truck}}
=d_{\mathrm{tr}}(p,c_1)
+\sum_{i=1}^{n-1}d_{\mathrm{tr}}(c_i,c_{i+1})
+d_{\mathrm{tr}}(c_n,p)
\]

运行过程中一旦得到更好的完整方案，立即更新 \(UB\)。

## 11.2 通用弱下界

对任意状态 \((s,v)\)，最终卡车必须返回仓库：

\[
LB_{\mathrm{return}}(s,v)=d_{\mathrm{tr}}(v,p)
\]

这是始终安全但较弱的下界。

## 11.3 当前固定顺序模型下的强下界

当前 Phase 3 递推要求卡车按既定顺序到达每个客户对应的服务/回收区域。

定义：

\[
H_n(v)=d_{\mathrm{tr}}(v,p)
\]

反向递推：

\[
H_{j-1}(v)=
\min_{x\in R(c_j)}
\left[
d_{\mathrm{tr}}(v,x)+H_j(x)
\right]
\]

则完成前 \(s\) 个客户后，从 \(v\) 出发的剩余成本下界为：

\[
LB_{\mathrm{ordered}}(s,v)=H_s(v)
\]

## 11.4 剪枝规则

若：

\[
F_s(v)+LB(s,v)>UB
\]

删除状态 \((s,v)\)。

若只需要一个最优解，可使用：

\[
F_s(v)+LB(s,v)\ge UB-\varepsilon
\]

若要保留全部等价最优路线，则使用严格大于。

## 11.5 严格证明

在当前固定顺序 DP 中，无论客户由卡车还是无人机服务，卡车递推路径都会在对应顺序位置到达该客户的候选区域：

- 卡车服务时到达客户节点，客户节点属于其区域；
- 无人机服务时，卡车到达相应回收节点；
- 多无人机批次递推通过各客户区域中的中间回收点连接。

有序区域下界：

1. 只计算卡车在这些区域之间的最短移动；
2. 忽略无人机飞行时间；
3. 忽略同步等待；
4. 对每个区域独立选择最有利节点。

这些放松均不会增加成本，所以 \(LB_{\mathrm{ordered}}\) 不高于任何真实剩余方案成本。

若当前累计值加下界已经高于可行上界，则以该状态为前缀的任何完整方案都不可能改善上界，删除安全。

### 重要适用边界

如果以后修改 Phase 3，使卡车不再按客户顺序到达每个客户区域，强下界证明失效。届时必须退回只使用 `LB_return`，或重新证明新的下界。

## 11.6 具体修改方式

1. 在进入正向 DP 前计算 truck-only 上界；
2. 对访问顺序反向计算 `ordered_lower_bound`；
3. 每个有限 `value` 状态写入后立即检查上界；
4. 被界剪掉的状态不创建父指针；
5. 完成一个更优终态后更新上界；
6. 先只在 `value` 层使用，不要一开始就在 `appr` 内部做复杂界剪枝；
7. 增加指标：
   - `phase3_initial_upper_bound`
   - `phase3_final_upper_bound`
   - `phase3_states_bound_pruned`
   - `phase3_lower_bound_seconds`
   - `phase3_bound_gap_histogram`

`tests/test_dp_ordered_lower_bound_pruning.py`

至少验证：

# 12. P7：Set-TSP 外部端点对支配剪枝

这一项是第二阶段最有研究价值的严格候选支配规则之一。

## 12.1 局部结构

考虑集合弧：

\[
S_i\to S_j
\]

当前候选外部端点对为：

\[
e=(a,b),\quad a\in S_i,\ b\in S_j
\]

其中：

- 当前集合从进入点 \(x\) 服务到离开点 \(a\)，成本 \(g_i(x,a)\)；
- 外部移动成本为 \(d_{\mathrm{tr}}(a,b)\)；
- 下一集合从进入点 \(b\) 服务到离开点 \(z\)，成本 \(g_j(b,z)\)。

该局部总成本为：

\[
C_e(x,z)=
g_i(x,a)+d_{\mathrm{tr}}(a,b)+g_j(b,z)
\]

## 12.2 支配规则

另一个候选：

\[
e'=(a',b')
\]

如果对全部：

\[
x\in S_i,\quad z\in S_j
\]

都有：

\[
g_i(x,a')+d_{\mathrm{tr}}(a',b')+g_j(b',z)
\le
g_i(x,a)+d_{\mathrm{tr}}(a,b)+g_j(b,z)
\]

则删除 `external[i,j,a,b]`。

## 12.3 严格证明

取任意使用候选 \(e\) 的完整 Set-TSP 可行解。

该解中：

- 前一集合进入 \(S_i\) 的外部弧保持不变，所以进入点 \(x\) 保持不变；
- \(S_j\) 离开到下一集合的外部弧保持不变，所以离开点 \(z\) 保持不变。

将局部选择：

\[
internal_i(x,a),\ external_{ij}(a,b),\ internal_j(b,z)
\]

替换为：

\[
internal_i(x,a'),\ external_{ij}(a',b'),\ internal_j(b',z)
\]

替换后：

1. 集合访问顺序不变；
2. 每个集合仍然一入一出；
3. 端点连续约束仍满足；
4. 流与 `select` 变量不变；
5. 局部成本不增加。

因此任何使用 \(e\) 的解都存在一个不更差、使用 \(e'\) 的对应解。候选 \(e\) 不可能是获得严格更优目标值所必需的，删除安全。

## 12.4 高效判断

预计算：

\[
\Delta_i(a',a)=
\max_{x\in S_i}
\left[g_i(x,a')-g_i(x,a)\right]
\]

\[
\Delta_j(b',b)=
\max_{z\in S_j}
\left[g_j(b',z)-g_j(b,z)\right]
\]

若：

\[
\Delta_i(a',a)
+d_{\mathrm{tr}}(a',b')
-d_{\mathrm{tr}}(a,b)
+\Delta_j(b',b)
\le 0
\]

则原来的“对全部 \(x,z\)”条件成立。

这把一次支配检查从枚举全部 \(x,z\) 转化为常数次查表。

## 12.5 相等候选处理

如果两个候选完全等价，它们可能互相支配。实现时必须指定稳定代表，例如：

- 按 `(a,b)` 的稳定节点编号排序；
- 相等时只允许较小编号支配较大编号；
- 禁止两个候选同时删除。

## 12.6 具体修改方式

在 `get_seq` 构造 `set_distance` 和 `distance` 后：

1. 为每个集合计算进入/离开差分上界矩阵；
2. 对每个有向集合对 `(i,j)` 构造端点候选；
3. 删除被其他候选支配的端点对；
4. 把保留索引传给 P1 的稀疏 `set_tsp`；
5. 若一个集合弧没有任何端点候选，则删除对应集合弧；
6. 调试模式记录每个删除候选及其支配者。

复杂度控制：

- 边界候选很小时可两两比较；
- 原始候选很大时先使用 P3 下界剪枝，再做支配；
- 记录支配预处理时间；
- 可按集合对并行，但首次实现先保持单线程保证可复现。

增加指标：

- `phase2_endpoint_pairs_before`
- `phase2_endpoint_pairs_dominated`
- `phase2_endpoint_dominance_seconds`
- `phase2_set_arcs_emptied_by_dominance`

5. 穷举小实例所有集合顺序和端点组合，剪枝前后成本一致；
6. Gurobi 模型剪枝前后成本一致；
7. 支配者本身后来被更强候选支配时，最终至少保留一个代表。

## 12.8 验收条件

- 每个删除候选都有可复核支配证据；
- 穷举小实例零误剪；
- 成本一致；
- 支配预处理时间不隐藏在 Gurobi 时间中。

# 13. P8：Set-TSP LP Reduced-Cost Fixing

## 13.1 基本规则

先求 Set-TSP 整数模型的 LP 松弛，得到：

- LP 最优值 \(z_{LP}\)；
- 当前可行整数上界 \(UB\)；
- 每个处于下界 0 的变量的 reduced cost \(rc_e\ge 0\)。

若：

\[
z_{LP}+rc_e>UB
\]

则固定：

\[
x_e=0
\]

如果只要求保留一个最优解，可以使用带容差的 `>=`。

## 13.2 严格证明

LP 最优对偶解为原 LP 提供全局下界。对一个在最优 LP 解中位于下界 0 的变量 \(x_e\)，将其增加到 1 至少需要付出 reduced cost：

\[
rc_e
\]

所以任何满足 \(x_e=1\) 的 LP 解目标值至少为：

\[
z_{LP}+rc_e
\]

整数可行域是 LP 可行域的子集，因此任何满足 \(x_e=1\) 的整数解成本也不会低于该值。

如果此下界已经高于当前整数可行上界，则 \(x_e=1\) 不可能产生更优整数解，可以固定为 0。

## 13.3 适用条件

只对以下变量使用简单规则：

- LP 值在容差内等于 0；
- reduced cost 为正；
- 已有经过可行性验证的整数上界；
- LP 求解达到最优状态。

对分数变量不能直接使用上述单变量公式。

若变量位于上界 1 且 reduced cost 为负，也可以推导固定为 1 的对称规则，但首次实现建议只做固定为 0，降低错误风险。

## 13.4 具体修改方式

1. P1-P7 完成后构造稀疏整数模型；
2. 创建 LP 松弛副本；
3. 求 LP 最优解；
4. 通过稳定变量名映射回整数模型；
5. 对满足规则的变量设置上界 0，或重建不包含这些变量的模型；
6. 优先对数量最大的 `external` 使用；
7. 再运行整数模型；
8. 记录 LP 预处理时间，不能只报告剪枝后的 MIP 时间。

增加指标：

- `phase2_lp_relaxation_value`
- `phase2_lp_relaxation_seconds`
- `phase2_reduced_cost_fixed_external`
- `phase2_reduced_cost_fixed_internal`
- `phase2_reduced_cost_fixed_select`

## 13.5 独立测试

新增：

`tests/test_set_tsp_reduced_cost_fixing.py`

至少验证：

1. 小模型中手工可计算 reduced cost；
2. 被固定变量不属于任何严格优于上界的枚举解；
3. LP 未最优时禁止剪枝；
4. LP 分数变量不使用简单规则；
5. 上界不可行时测试必须失败；
6. 剪枝前后整数最优成本一致；
7. 容差边界场景。

## 13.6 验收条件

- LP 状态不是 optimal 时自动停用；
- 上界经过独立可行性检查；
- 成本一致；
- 总时间必须包含 LP 时间；
- 论文中应将其说明为通用 MIP 剪枝，而不是主要算法创新。

# 14. P9：强制集合弧和端点弧下界剪枝

P9 是 P3 与 P8 的增强版，只对仍然难以判断的候选做更强但更昂贵的受限下界。

## 14.1 强制集合弧

对集合弧：

\[
select_{i,j}=1
\]

求一次带该固定条件的 LP 松弛，得到：

\[
LB_{i,j}
\]

若：

\[
LB_{i,j}>UB
\]

则删除：

- `select[i,j]`
- `flow[i,j]`
- 全部 `external[i][j][a][b]`

## 14.2 强制端点弧

对仍然可疑的外部端点候选：

\[
external_{i,j,a,b}=1
\]

求受限 LP 下界：

\[
LB_{i,j,a,b}
\]

若其高于上界，则删除该端点弧。

## 14.3 严格证明

固定候选后的 LP 可行域包含固定该候选后的所有整数可行解，因此：

\[
LB_{\mathrm{forced}}
\le
OPT_{\mathrm{integer,forced}}
\]

若该下界已经高于一个已知可行整数解，则任何包含该候选的整数解都不可能改善上界，删除安全。

## 14.4 控制求解成本

不能对全部端点弧盲目求独立 LP，否则剪枝预处理可能比原问题更慢。

推荐顺序：

1. 先做 P3 指派下界；
2. 再做 P7 支配；
3. 再做 P8 reduced-cost；
4. 只对剩余集合弧做强制 LP；
5. 只有当集合弧仍包含大量端点候选时，再挑选 reduced cost 接近阈值的端点弧；
6. 给全部强制 LP 设置总时间预算；
7. 可以复用 LP 基、使用 warm start；
8. 多个集合弧可并行实验，但正式可复现对照先固定单线程。

## 14.5 具体修改方式

建议增加一个预处理器，输入：

- 当前稀疏模型；
- 可行上界；
- 时间预算；
- 待检查候选列表。

输出：

- 被固定为 0 的集合弧；
- 被固定为 0 的端点弧；
- 每个删除候选的受限 LP 下界证据；
- 总预处理时间。

增加指标：

- `phase2_forced_arc_lp_count`
- `phase2_forced_arc_lp_seconds`
- `phase2_forced_set_arcs_pruned`
- `phase2_forced_endpoint_arcs_pruned`
- `phase2_forced_arc_timeout_count`

## 14.6 独立测试

新增：

`tests/test_set_tsp_forced_arc_bound_pruning.py`

至少验证：

1. 小实例穷举受限真实最优值；
2. 受限 LP 下界不超过受限整数最优值；
3. 被删除候选不属于严格更优解；
4. LP 超时/非最优时不得剪枝；
5. 时间预算耗尽后安全停止预处理；
6. 剪枝前后整数最优成本一致。

## 14.7 验收条件

- 每次删除都有受限 LP 下界记录；
- LP 非最优不删除；
- 总时间包含全部受限 LP；
- 只在净收益为正的规模上默认启用。

# 15. P10：有损裁剪，只作为单独实验组

以下方法可能非常快，但不能与 P1-P9 一起宣称“严格保最优”。

## 15.1 当前重叠节点最近客户分配

`get_convex_sets` 会把同时落入多个客户区域的节点只分配给最近客户。

风险：

- 同一个路网节点可能是另一个客户更好的发射/回收点；
- 删除其集合成员身份可能改变最优客户访问顺序和端点组合；
- 距离相等时，当前 `<=` 与客户迭代顺序会决定归属。

因此它是启发式候选裁剪，而不是严格状态支配。

## 15.2 当前边界节点裁剪

`get_boundary_convex_sets` 当前只通过 `nx.neighbors` 检查后继节点。

在有向图上可能存在：

- 节点具有区域外前驱；
- 但全部后继仍在区域内。

这种节点是进入边界，却可能被当前代码删除。

此外，即使使用“入边界 ∪ 出边界”，如果没有对所有边界对预计算能够代表全部内部发射/回收策略的精确闭包，也不能证明删除内部节点安全。

特别是在：

- 候选区域重叠；
- 卡车最短路可以离开并重新进入区域；
- 内部服务成本使用全局路网最短距离；

的情况下，简单边界论证不足。

## 15.3 Top-K 集合弧

每个集合只保留距离最近的 K 个后继，在非对称 TSP 中可能删除最优环的必要远距离连接。

只能作为 C 级方法，建议：

1. 从较大 K 开始；
2. 若模型不可行自动扩大 K；
3. 与严格剪枝解比较成本差；
4. 报告 K、时间、成本 Gap。

## 15.4 Beam DP

每层只保留前 B 个 `VALUE` 状态可能删除一个当前成本稍高、但未来回仓或服务剩余客户更便宜的状态。

如果使用，应按：

\[
F_s(v)+LB(s,v)
\]

排序，而不是只按 \(F_s(v)\) 排序，但仍然属于有损裁剪。

## 15.5 实验隔离要求

所有 C 级方法必须：

- 使用单独配置开关；
- 输出 `heuristic_pruning_enabled=true`；
- 与 P1-P9 的严格剪枝结果分别报告；
- 不得用“保持完整解空间”“无损”描述；
- 给出成本 Gap、不可行率和运行时间分布。

# 18. 每一步的统一验收模板

每个优先级完成后都执行以下检查。

## 18.1 正确性

- 剪枝开/关目标值一致；
- 路线重建可行；
- 每个客户恰好服务一次；
- 无人机航程不超过限制；
- 卡车路径可达；
- 每个删除状态能说明删除原因；
- 小实例穷举零误剪。

## 18.2 性能

- 剪枝预处理时间；
- 求解时间；
- 总时间；
- 变量/状态剪枝率；
- 距离查询数；
- 峰值内存；
- Gurobi 节点数。

## 18.3 稳健性

- Manhattan 与 Boston；
- 不同客户数；
- 不同仓库数；
- 不同无人机数；
- 不同航程；
- 有向非对称距离；
- 候选区域重叠程度；
- 稀疏和稠密区域。

## 18.4 失败回退

任何预处理器遇到：

- 数值异常；
- LP 未达到最优；
- 上界未通过可行性检查；
- 索引映射不一致；
- 时间预算耗尽；

都必须安全退回“不应用该项剪枝”，而不是继续删除候选。

# 19. 最终建议

如果目标是同时产出 Set-TSP 和 DP 两部分改进，建议把论文贡献组织为两条主线：

1. **Cost- and dominance-aware sparse Set-TSP**
   - 结构零变量；
   - 指派下界；
   - 端点对支配；
   - reduced-cost/强制弧 fixing。

2. **Bitmap- and label-pruned ordered truck-drone DP**
   - 稀疏可达状态；
   - 共同发射点位图；
   - 状态支配；
   - 有序区域下界。

其中最值得优先完成并形成正式实验的是：

1. P3 Set-TSP 指派下界；
2. P4 DP 共同发射点位图；
3. P6 DP 有序区域下界；
4. P7 Set-TSP 端点对支配。

P8-P9 可以增强求解效果，但属于较通用的整数规划技术；P3、P4、P6、P7 更容易形成与 MA-FSTSP 状态结构直接相关的方法贡献。
