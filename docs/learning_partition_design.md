# 面向后续求解性能的 MA-FSTSP 学习型客户划分方案

研究目标：保持原论文各车组完工时间之和的配送目标，在最终配送成本接近时，减少客户划分、Set-TSP 与联合调度的实际计算耗时。

推荐方法：**用真实后续求解结果训练客户调整评价器，在 MST 初始划分上选择迁移、交换或小簇迁移。** 第一阶段决定调整，第二阶段产生客户顺序，第三阶段提供最终配送成本标签。第三阶段在本研究中作为固定评价器。

这是一个可以从表格数据和监督学习开始的项目。第一项需要学会的任务是：给定一次客户调整，预测它是否值得执行。

**2. 问题应怎样表述**

客户数量不均衡是需要检查的现象，最终问题是：**第一阶段使用的划分评价，与第二、第三阶段真正的成本和计算难度存在偏差。**

设完整实例为 \(x\)，包含地图、全部客户、仓库、无人机参数；划分为 \(P=(C_1,\ldots,C_m)\)。固定第二阶段求解器为 \(S_2\)，第三阶段为 \(S_3\)，固定运行策略为 \(\Omega\)，包括求解预算、停止条件、随机种子和超时回退。

\[
o_i=S_2(x,p_i,C_i;\Omega),\qquad
D_i=S_3(x,p_i,C_i,o_i;\Omega).
\]

\[
J(x,P;\Omega)=\sum_{i=1}^{m}D_i.
\]

这里 \(D_i\) 是模拟配送过程中的车组完工时间；以下 \(t\) 是计算机运行程序的秒数，两者必须分开。

当前代码按车组串行计算，因此：

\[
t_2(P)=\sum_i(t_{\mathrm{distance},i}+t_{\mathrm{build},i}
+t_{\mathrm{optimize},i}+t_{\mathrm{extract},i}),
\]

\[
t_{\mathrm{online}}(P)=t_{\mathrm{instance\ prep}}+t_{\mathrm{partition}}
+t_{\mathrm{feature}}+t_{\mathrm{inference}}+t_2(P)+\sum_i t_{3,i}.
\]

地图级全对距离预处理另报一次性成本，并给出冷启动总耗时；如按批次摊销，所有方法使用同一摊销方式。模型加载计入冷启动指标，也单独报告常驻内存的推理耗时。

以固定基线划分 \(P_0\) 为参照，采用成本约束形式：

\[
\min_P\ t_{\mathrm{online}}(P)
\quad\text{s.t.}\quad
J(P)\le (1+\varepsilon)J(P_0).
\]

这个约束表达“成本接近时加快求解”。同时报告 \(J(P)\)，绘制成本—耗时曲线。若出现明显更低成本的候选，应保留在候选集合中，避免只围绕基线容忍带追求时间。

建议先报告 \(\varepsilon\in\{0,1\%,3\%,5\%\}\) 的完整曲线；具体可接受值属于研究设置，不能把历史文件中的 5% 自动当成当前要求。严格以成本为先时，可在已评估候选的最小成本附近建立容忍带，再比较耗时。

客户数方差、最大组大小和最大单组计算时间都作为诊断指标。当前串行架构不能用最大单组时间代替总计算时间；如果以后改为并行求解，需要在固定 CPU 总线程数、内存和调度条件下重测。

**3. 为什么不能只按客户数量均分**

以下是从本地 `set_tsp` 的变量创建循环直接推导的规模，而非运行时间复杂度定理。

对一个含 \(q\) 个客户的非空车组，令 \(b_c\) 为客户 \(c\) 的边界候选点数：

\[
n=q+1,\qquad M=1+\sum_{c\in C_i} b_c.
\]

仓库作为一个单点集合。当前稠密建模创建：

| 变量 | 创建数量 |
|---|---:|
| 集合访问顺序 `select`，二元 | \(n^2\) |
| 集合流 `flow`，连续 | \(n^2\) |
| 集合内部点对 `internal`，二元 | \(1+\sum_c b_c^2\) |
| 集合之间点对 `external`，二元 | \(M^2\) |

因此建模前二元变量数量为：

\[
N_{\mathrm{binary}}=n^2+1+\sum_c b_c^2+M^2.
\]

这包含随后被约束固定的变量；Gurobi 预处理可能删掉一部分。空组在进入 MILP 前直接返回，实际没有创建这些变量。

例如两个组都含 10 个客户，若每个客户分别有 5 个、20 个候选点，`external` 数量分别是 \(51^2=2601\)、\(201^2=40401\)，相差约 15.5 倍。客户数相同，建模规模仍可能差很多。

另一方面，组的空间形状、仓库往返、道路方向性、候选点之间的距离结构、相近成本解的数量，也可能影响 MILP 搜索。变量较少不保证每次都更快，需要数据验证。

本地还存在两种不同集合：

- Phase 2 使用按全部客户竞争归属、再提取边界的集合。
- Phase 3 的 `self.regions` 使用半航程内完整道路节点集合，允许不同客户的区域重叠。

因此应分别提取两类集合的大小和结构。不能把 Phase 2 边界集合的重叠率作为无人机协同特征，它们在当前构造下本来就是互斥的。

另一份 [代理模型审计](../results/learning/review/performance_audit.json) 记录：

- 训练数据共 195 行，但只有 15 个原始实例，训练/验证/测试分别为 9/3/3 个实例；195 行不等于 195 个独立实例。

这些记录支持优先解决一个具体问题：模型应能在**同一实例、相近划分之间**判断调整收益。只拟合跨规模的总耗时，可能学到“大组较慢”，仍然不会选择好动作。

**5. 推荐的学习架构**

```mermaid
flowchart LR
  X[地图、客户、仓库与无人机参数] --> P[MST 初始划分]
  P --> A[生成有限个客户调整候选]
  A --> F[提取调整前后结构特征]
  F --> M[预测成本变化与计算收益]
  M --> C[在成本容忍范围内选候选]
  C --> S[Set-TSP 求访问顺序]
  S --> D[固定第三阶段求联合配送]
  D -. 离线生成真实标签 .-> T[训练与验证数据]
  T -. 拟合 .-> M
```

离线阶段可以花时间求解很多实例来学习经验。在线阶段只提取特征、调用模型选择候选，再对选出的划分执行正常后续求解。

首个版本推荐“**一个初始划分 + 一批候选 + 一次选择**”。成功后再扩展为最多 3～5 步的调整。这样容易定位问题，也不会一开始就承受多步预测误差累积。

候选动作包括：

| 动作 | 含义 | 对下游求解的影响范围 |
|---|---|---|
| `stay` | 保持初始划分 | 无 |
| `relocate(c,i,j)` | 把客户 c 从组 i 移至组 j | 两组 |
| `swap(c,d,i,j)` | 交换两组的客户 | 两组 |
| `move_cluster(U,i,j)` | 把相邻的 2～3 个客户共同移动 | 两组 |

生成候选时优先考虑：候选点负担较大的组、两个仓库归属代价相近的客户、与邻组客户接近的客户，以及 MST 的小型子树。交换能在人数不变时改变后续难度；小簇移动可保留邻近客户的协同机会。

保留少量随机候选供离线探索，避免数据只包含启发式已经认为好的动作。在线将候选数限制在例如 20～50 个并批量预测；具体数量根据实测特征开销调整。所有候选保持客户恰好归属一次，允许空车组，不强制所有仓库都被使用。

**6. 标签如何设计**

标签分为“原始车组运行记录”和“客户调整收益”。前者可复用，后者直接对应第一阶段的决策。

**6.1 每个车组记录的原始标签**

| 字段 | 定义 | 用途 |
|---|---|---|
| `final_delivery_cost` | 固定 Phase 2→3 流程得到的车组完工时间 | 配送质量主标签 |
| `phase2_distance_seconds` | 为当前 Set-TSP 准备距离张量的时间 | 避免漏算 Python 开销 |
| `phase2_build_seconds` | 创建变量、约束、目标的时间 | 建模负担标签 |
| `phase2_optimize_seconds` | `model.optimize()` 阶段时间 | 求解器耗时 |
| `phase2_extract_seconds` | 从 MILP 解恢复访问顺序的时间 | 完整计时 |
| `phase2_wall_seconds` | 上述阶段的完整实际耗时 | 主要效率标签 |
| `phase3_seconds` | 固定顺序调度耗时 | 检查第二阶段收益是否转移成第三阶段负担 |
| `status`、`has_incumbent`、`gap` | 求解状态、是否有可行解、Set-TSP 间隙 | 解释标签质量 |
| `timeout`、`fallback_used` | 是否触及停止预算、是否回退 | 难例和回退识别 |
| `num_vars`、`num_binary`、`num_constrs`、`work` | 模型规模及求解工作量 | 诊断与辅助训练 |

Set-TSP 目标值可作为辅助标签，但不能代替 `final_delivery_cost`。Set-TSP 的最优性间隙也不是 MA-FSTSP 最终配送方案的全局最优性间隙。

这里的真实标签是“实际运行固定启发式得到的结果”，不代表 MA-FSTSP 全局最优值，也不代表任意不同求解器都适用的通用价值。

**6.2 直接学习一次调整的变化**

对迁移或交换，受影响的两个组为 \(i,j\)，调整后用撇号表示。以同一原始实例的固定基线成本 \(J_0\) 和二阶段时间 \(t_{2,0}\) 归一化：

\[
y_C(a)=\frac{D'_i+D'_j-D_i-D_j}{J_0},
\]

\[
y_T(a)=\frac{t_{2,i}+t_{2,j}-t'_{2,i}-t'_{2,j}}{t_{2,0}}.
\]

\(y_C>0\) 表示配送成本恶化；\(y_T>0\) 表示第二阶段节省时间。再用同样方式记录 \(y_{23}\)，度量第二、第三阶段合计节省时间。对于实际非空实例，基线成本和时间为正；实现只需为数值除法提供极小分母保护。

这些归一化基准用于离线生成训练目标和评估。在线模型输入不能包含当前实例尚未运行得到的真实 \(J_0,t_{2,0}\)，而应使用可提前计算的结构与几何特征。模型直接预测无量纲变化。

当所有候选从 \(P_0\) 出发时，成本约束就是 \(y_C(a)\le\varepsilon\)。如果以后采用多步调整，每一步相对当前状态的增量需要累计，并重新评价最终划分相对 \(P_0\) 的变化，不能把每一步的 \(\varepsilon\) 当成独立可花费的成本额度。

举例，以下数字只演示标签定义：

| 候选 | 最终总配送成本 | 二阶段总耗时 | 相对基线成本变化 | 二阶段节时率 |
|---|---:|---:|---:|---:|
| MST 基线 | 100 | 80 s | 0 | 0 |
| 调整 A | 100.8 | 55 s | +0.8% | +31.25% |
| 调整 B | 108 | 40 s | +8% | +50% |
| 调整 C | 99.5 | 75 s | −0.5% | +6.25% |

若成本容忍度为 1%，A 与 C 可参与速度比较，B 被筛除。若目标采用严格成本优先的排序，则 C 优先。这种差别由明确的研究设置决定。

不要把“原 MST 分配到哪个仓库”当作目标标签；那样主要是在学习复现 MST。也不要求给每个实例求出全局最优划分，局部候选的实际结果已经能够提供有用监督。

**6.3 超时标签必须区分两种含义**

第一种目标是“部署时预算策略下实际花了多少时间”。例如固定 Set-TSP 优化预算、记录实际耗时，有解就使用 incumbent，无解则调用预先固定的回退路径；此时被截断的实际时间是该策略的完整运行结果，可以用于回归。

第二种目标是“不设这个预算，达到指定最优性间隙需要多久”。超时只说明所需时间至少超过已观察时间，是右删失数据，不能把 30 秒超时标成恰好 30 秒完成。

首个版本建议使用第一种定义，另加超时风险分类。这样不需要一开始实现生存分析。若研究无限制完成时间，则需要删失损失或生存模型，并对部分困难样本增加预算采集完成时间。

`TimeLimit` 不是整个 Python 调用的时间上限，也可能被优化器略微超出。严格总预算需要在建模、优化和回退之间分配剩余时间，必要时使用工作进程的整体超时控制。[Gurobi 参数文档](https://docs.gurobi.com/projects/optimizer/en/current/reference/parameters.html#timelimit)

第一阶段学习收益必须在所有对照使用相同停止和回退策略时比较；不能只给学习方法限时，然后与无限制基线比较速度。

**7. 模型输入：保留哪些信息**

首个版本建议约 40～80 个表格特征，按实际消融精简。已有数据中的字段可以作为起点。

| 类别 | 建议特征 | 与后续性能的联系 |
|---|---|---|
| 车组规模 | 客户数、边界点总数、边界点平方和、最大/方差、上述变量数量公式 | 建模工作量 |
| 第三阶段区域 | 完整 `regions` 大小的均值、最大值、平方和 | DP 状态与转移负担 |
| 仓库联系 | 仓库到组、组到仓库的路网距离统计；客户对相邻仓库的归属差 | 往返与改派成本 |
| 组内结构 | 近邻距离、MST 长度、长连接边比例、离散度、组内小簇数量 | 路线紧凑性与难度 |
| 道路方向 | 双向距离均值与差异、进出方向分别统计 | 单行道路造成的不对称 |
| 无人机协同 | 完整区域重叠、近邻客户距离/航程、道路绕行相对飞行距离的比例 | 共同起飞回收和绕行节约的可能性 |
| 动作特征 | 动作类别、移出/移入组上述特征的前值、后值、差值；客户邻近关系 | 直接判断此次调整 |
| 实例上下文 | 全部客户数、仓库数、每车无人机数、速度比、航程、全局候选点统计 | 适应不同规模和车辆参数 |

经纬度先转成合理的局部距离表示或使用现有距离函数，避免用“经纬度差”直接充当公里。保持卡车距离、无人机距离及速度的单位一致。

阶段一集合距离可以用于特征和候选筛选。若某些近邻集合距离需要大量点对枚举，先计算共享摘要、缓存或固定数量采样，避免提取特征比节约的求解时间还长。

实际 Set-TSP 解、实际 Phase 3 成本、Gurobi `Runtime`、`Work`、`MIPGap`、分支节点数均属于运行后信息，不能直接作为无需调用求解器的划分模型输入。若另做短探测模型，其探测开销要单列并计入在线时间。

**8. 学习方法与训练损失**

**8.1 首个可实施模型：监督式客户调整评价器**

使用 scikit-learn 的梯度提升树，分别训练：

1. 成本变化模型 \(f_C(z)\to\hat y_C\)。
2. 第二阶段节时模型 \(f_T(z)\to\hat y_T\)。
3. 下游合计节时模型 \(f_{23}(z)\to\hat y_{23}\)，用于端到端收益筛选。
4. 数据中有足够正负样本时，再训练超时风险分类器。

首个实现可以只训练前两个回归器，同时实际测量第三阶段；增加第三个回归器用于避免耗时转移。模型不需要 GPU，也不需要对 Gurobi 求导。

回归损失可先用绝对误差，降低少数异常耗时的影响。成本模型再拟合较高分位数，例如 90% 或 95%，为决策提供保守成本估计。树模型与分位数回归可直接使用 [HistGradientBoostingRegressor](https://scikit-learn.org/stable/modules/generated/sklearn.ensemble.HistGradientBoostingRegressor.html)。

按完整实例划分训练/验证集。不要让估计器内部随机按行的早停划分跨越这些边界；可关闭内部早停，在固定实例验证集上比较迭代次数。调参和阈值选择不接触最终测试集。

第一阶段按以下规则选择候选：

\[
\widehat y_{C,\mathrm{upper}}(a)\le\varepsilon,
\qquad \widehat y_{23,\mathrm{lower}}(a)>\text{预计额外开销比例}.
\]

在满足成本容忍条件的候选中，按预计净节时排序。没有可信收益时输出 `stay`。成本明显改善但节时较少的候选也保留供成本—时间曲线评估；若采用严格成本优先设置，则先建立最低预测成本附近的容忍带，再按净节时排序。

分位数是统计估计，不是逐实例保证。模型会在多个候选中主动挑选，普通单样本覆盖率也不能自动转换成“挑中动作”的覆盖率；需要在独立验证实例上完整运行筛选策略并统计违约。

**8.2 必须增加同一实例内的决策训练与评价**

优先直接拟合动作差值，而不是分别预测两个大绝对数再相减。后者即使绝对误差小，也可能使微小收益的符号出错。

当候选数量与训练数据足够时，可增加同一状态内的成对排序训练。对真实成本可接受的候选 \(a,b\)，若 \(a\) 实际更快，则学习分数 \(s_a>s_b\)：

\[
\mathcal L_{\mathrm{rank}}=\log(1+\exp(-(s_a-s_b))).
\]

只有时间差超过重复测量噪声的候选对才参与强排序；其余标为近似平局。按真实收益幅度给样本权重，并降低大量同一原始实例衍生动作对训练的支配。

树模型起步阶段通过动作差值回归和验证集选择即可实现主要目标；上式是后续小型神经网络排序器的可选扩展，不要求首版同时实现。

**8.3 什么时候再引入 GNN 或强化学习**

| 方法 | 适合研究的问题 | 当前安排 |
|---|---|---|
| 手工候选点负担 + 几何约束 | 不学习能否已经显著改善 | 必做强基线 |
| 梯度提升树动作评价器 | 结构摘要能否预测真实局部收益 | 主方案起点 |
| GNN/集合编码器 + 同样标签 | 细粒度客户关系是否超出摘要特征能力 | 有充分数据后升级 |
| 单层强化学习 | 多步调整是否需要考虑长期收益 | 监督模型稳定后再评估 |
| 分层强化学习 | 大动作空间和长决策链是否值得分层 | 暂不作为首个实现 |

GNN 若有必要，图的节点优先使用客户和仓库，边特征编码双向路网距离、飞行距离、区域关系；组表示使用 sum/mean/max 聚合，再预测两组调整收益。不要直接把整张 55K 道路图塞进首个模型。

强化学习若使用代理模型奖励，需要定期用真实求解结果校准，并对策略产生的新状态追加标签。否则策略可能越来越擅长改善错误预测。现有少量历史结果尤其不支持直接把 HRL 模型继续放大当作下一步。

**9. 训练数据怎样生成**

按以下流程建立两个文件：`group_evaluations.csv` 和 `action_labels.csv`。

1. 在指定路网上采样原始实例，包含客户和仓库位置。
2. 在生成任何动作前划分训练、验证、测试原始实例。
3. 每个实例计算一次全局边界集合、完整区域、集合距离摘要与 MST 划分。
4. 评价原始划分的车组，得到基线成本与阶段耗时。
5. 为初始划分生成迁移、交换、小簇迁移及 `stay`；包含改善、恶化和近似平局样本。
6. 对动作影响的两个新组调用相同 Phase 2→3 评价器，未改变的组复用标签。
7. 从前后结果计算成本变化与时间收益，保存动作特征和运行元数据。
8. 训练并在完整验证实例上选阈值，随后进行独立测试。

当前边界集合依赖**全部客户**，但在固定实例内不随分组改变；`self.regions` 也固定。因此只重算两个受影响组有明确依据。若以后把边界集合改为“每组内部重新构造”，必须重新定义这个评价与缓存条件。

车组缓存键至少包含：地图内容指纹、完整原始实例/候选集合指纹、当前组客户及仓库、无人机参数、集合构造规则、距离规则、代码版本、求解策略及种子。仅用“仓库 + 组内客户”可能误复用不同实例的边界集合。

客户/候选点排序也要固定；稳定排序后生成新的统一实验基线。若保留原有顺序，则将其写入键，避免同一成员集合但 MILP 构造顺序不同的记录被混用。

建议的数据规模：

| 阶段 | 原始实例 | 每个实例动作数 | 目的 |
|---|---:|---:|---|
| 采集试运行 | 30，覆盖 50/100/150 客户 | 约 10 | 测标签耗时、噪声、可改善动作比例 |
| 首轮正式训练 | 约 300 | 约 20 | 验证模型是否超过手工基线 |
| 扩展 | 500～1000 或按学习曲线追加 | 随不确定性选取 | 更大规模、不同地图与 GNN |

这些是启动规模，不是保证效果的门槛。以 5 组、10 个两组动作计算，30 个实例至多需要约 \(30(5+2\times10)=750\) 次车组评价，去重后可更少。若平均每次 10 秒，约 2.1 小时；若 60 秒，约 12.5 小时。这只是预算算例，先用真实采集速度估计。

300 个实例、每例 20 个动作，对应至多约 13,500 次车组评价。不能把生成监督标签视为没有成本。先用便宜特征或 LKH 顺序筛选，再对有代表性的候选运行 Set-TSP；保留随机样本，控制筛选偏差。LKH→DP 与 Set-TSP→DP 的成本应标注不同 `fidelity`，不能混成同一种真值。

时间标签采集应在目标服务器上固定线程数、停止规则与种子，并随机化候选执行顺序。对接近决策边界、时间差很小的候选重复测量，使用中位数和噪声带。`Work` 可帮助诊断，但其确定性有相同模型、硬件和设置等条件，不能直接当成跨机器可迁移秒数。[Gurobi 模型属性文档](https://docs.gurobi.com/projects/optimizer/en/current/reference/attributes/model.html#work)

划分训练测试时以原始实例为单位；如果不同客户规模共享同一个采样母实例、客户子集或仓库种子，应按实例族一起划分。实现可以使用 [GroupShuffleSplit](https://scikit-learn.org/stable/modules/generated/sklearn.model_selection.GroupShuffleSplit.html)。

**10. 成本保护与在线速度之间的边界**

快速运行模式：不运行所有候选的真实后续求解器，用模型筛选并只求解选定划分。这样具备加速可能，但相对基线成本的限制是统计性的，因为真实 \(J(P_0)\) 此时还未知。

严格核验模式：实际求解基线和选定候选，比较真实成本，不合格则返回基线已有解。这能保证相对这个已计算基线解的成本容忍度，但基线和候选的全部求解时间、回退时间都必须计入，可能失去加速优势。

两种模式分别报告。不能先调用真实基线得到成本、再把这笔耗时从学习方法中删掉；也不能声称代理模型提供硬约束保证。

如果真实求解结果已经作为当前在线任务的合法已有输入，可以明确报告“从已有解继续改进”的场景，其基线也必须从同样已有解开始。这与首次求解属于不同实验。

**11. 公平实验和通过条件**

所有方法使用相同地图、客户、仓库、距离语义、Phase 2/3、停止策略、线程和随机种子。

| 对照 | 检查内容 |
|---|---|
| 原始 Set-MST | 相对原仓库流程的实际收益 |
| 明确对称化集合距离的 MST | 区分方向处理收益与学习收益 |
| 带几何限制的客户数平衡 | 检查学习是否只是在均分人数 |
| 带几何限制的候选点/变量规模平衡 | 检查学习是否只是在均分建模负担 |
| 相同候选集合下的手工动作评分 | 保持搜索空间与推理预算一致 |
| 相同候选集合下的随机动作 | 检查学到的选择价值 |
| 监督式动作评价器 | 主方法 |
| 对全部候选真实求解后选择 | 估计候选集内可实现改进空间；计入全部时间，不称作全局最优 |

首先运行最后一种候选集评价的小规模诊断：如果在成本容忍范围内，候选里根本没有更快的划分，模型无法创造收益，需要调整候选集合或重新评估研究假设。

消融包括：只用客户数、加入候选点规模、加入道路结构、加入无人机区域、只用阶段二目标作质量标签、使用阶段三最终成本标签、绝对值预测与动作差值预测、是否进行成本风险控制。候选生成预算保持一致。

模型指标：同一实例内的候选排序、收益方向准确率、选中动作相对候选集最好动作的损失、成本容忍违约率和校准情况。全局 MAE、R²、Spearman 只作辅助。

最终求解指标：

- 最终总配送成本的配对相对变化、均值、中位数、P90 和最坏恶化。
- 满足成本容忍度的实例比例；在满足条件的实例上的节时率，以及所有实例上的时间。
- 第二阶段完整耗时、第三阶段耗时、学习划分开销、包含这些部分的端到端耗时。
- 时间分布的 P50/P90/P95、超时率、无 incumbent 率、回退率。
- 最大车组客户数、候选点总数、变量数与内存峰值。

使用完整实例为重采样单位计算配对 bootstrap 区间；同一实例的多个车组不是独立样本。相同方法换 3 个训练种子有助于识别偶然训练收益；正式目标阈值由验证集确定，最终测试只评价一次选定设置。

端到端验收应清空或隔离可直接返回求解结果的车组缓存，记录真实开始结束时间。地图最短路缓存可共享，但所有方法的状态一致；不能拿缓存加载耗时与真实 MILP 求解相比，也不能用历史时间之和冒充当前墙钟时间。

至少分别测试：同图新客户、新仓库布局、50/100 训练到 150 的规模外推、不同路网。当前名为 `boston_11k` 的默认配置读取的是 `nyc_11000.graphml`，因此不是独立城市泛化测试。[配置依据](../config.py)

**12. 在生成大规模标签之前应统一的实现语义**

这些是可复现实验必须明确的具体事项，不需要增加大量泛化数据校验。

1. `set_mst` 在无向 `nx.Graph` 中反复写入有向代价，反向循环可能覆盖同一边。基线应保留原实现作对照，并增加显式对称化方式，例如往返均值。学习方法与手工方法使用相同方式；该修正的收益不能算入学习收益。
2. `get_seq` 的集合内部代价当前形如 `max(truck_distance, drone_distance) / speed`；Phase 3 则使用 `max(truck_distance, drone_distance / speed)`。在卡车速度归一化为 1 的解释下，两者不同。还应核对内部进出索引的方向。先固定一个有记录的评价器，相关修正作为独立对照统一施加，避免混合语义生成标签。
3. 当前 `set_tsp` 只设置日志参数，没有显式 `TimeLimit`，也没有在恢复 `.X` 前检查可行解状态。采集器需要明确预算、incumbent 读取和无解回退，所有方法共用。
4. 当前地图标准化按端点球面距离生成边权，而不是直接使用 OSM 道路折线长度。研究应明确采用哪种道路距离，所有标签和测试一致，不能混用缓存。
5. `model.regions` 在构造函数中计算，而现有 `solve_seconds` 从外部构造完成后开始。完整在线计时需要包含实例级区域预处理，避免遗漏成本。
6. 第一阶段的图构造、全对最短路和第三阶段也可能占较大耗时；改进客户划分不会自动消除这些开销。先报告时间分解，评估可达到的端到端加速上限。

后续代码中的函数说明、关键特征/数据结构注释使用中文。需要验证代码时建立新的测试文件，例如：

- `tests/test_learning_partition_labels.py`：两组增量与全实例成本差一致、超时标签语义。
- `tests/test_learning_partition_candidates.py`：迁移/交换客户覆盖、空组和 `stay`。

学习顺序可按以下概念推进：一行样本和标签 → 训练/验证/测试 → 回归模型 → 动作选择 → 独立真实求解验收。强化学习、GNN 和可微优化属于后续选修内容。

**15. 方法定位与相关工作**

[Learning to Delegate for Large-scale Vehicle Routing](https://arxiv.org/abs/2107.04139) 将子问题选择建模为学习任务，再交给既有子求解器处理。它为“学习选择 + 保留优化器”的结构提供了相关先例；其任务和实验收益不能直接迁移为 MA-FSTSP 的结论。

[Smart “Predict, then Optimize”](https://arxiv.org/abs/1710.08005) 强调评价预测所诱导的决策损失。本方案借鉴这个评价原则，但以动作差值回归和候选排序为起点，不声称直接应用 SPO+，也不需要对当前整数求解器反向传播。

可研究的贡献是：利用固定 Set-TSP→DP 的真实反馈，设计面向配送质量与计算负担的局部划分标签，并在成本约束下选择客户调整；进一步检验道路结构与无人机协同特征是否带来超出人数/候选点平衡的收益。

“使用了神经网络”“划分更加均匀”“代理模型损失更低”都不能单独证明贡献。所需证据是：在相同后续求解器和资源设置下，对未参与训练的实例，真实配送成本满足选定容忍度，真实端到端计算表现优于强手工基线，并有清楚的失败边界。
