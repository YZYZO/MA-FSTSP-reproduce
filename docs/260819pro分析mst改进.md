# MA-FSTSP 第一阶段客户划分改进方案

## 结论

有更合适的方法，但不建议仅把 MST 换成 K-means、谱聚类之类的通用聚类算法。

对于当前研究，较合理的改进路线是：

1. **先修正当前 MST 分区中的有向距离处理问题**；
2. 用**多仓库根生成森林**替代现有“先求一个全局 MST、再在树上划分”的实现，作为低风险改进基线；
3. 在此基础上加入**解码器引导的 relocate/swap 局部搜索**；
4. 后续升级为**同时优化客户分组与访问顺序的 ALNS**，作为论文中的主要创新候选。

其中，最推荐的是第 3 项：**MST/MSF 初始化 + 路径代价感知的局部搜索**。它与现有代码兼容，改动量可控，又比单纯树分区更贴近最终目标。

## 一、当前第一阶段实际在做什么

论文的整体框架可以概括为：

- 第一阶段：将客户划分给不同仓库；
- 第二阶段：对每个仓库对应的客户集合求 Set-TSP 访问顺序；
- 第三阶段：在固定顺序下，通过动态规划构造卡车—多无人机协同路线。

第一阶段并不是直接使用客户之间的道路距离，而是先给每个客户构造候选服务点集合，再通过论文的集合间近似距离构造“仓库—客户—客户”完全图，随后使用 NN 或 MST 完成分区。

原仓库中的实现与此一致：

- `set_mst()` 构造 `nx.Graph`；
- 计算仓库—客户、客户—客户之间的集合化边权；
- 调用 `mst_partition()`；
- `mst_partition()` 首先执行 `nx.minimum_spanning_tree(graph)`，然后只在这棵 MST 上通过树形动态规划划分客户。

你的 `260801-h2h` 分支仍然保留了这套分区逻辑，主要变化是将卡车最短路查询替换成了按需的 H2H 距离后端。

## 二、当前 MST 方法的主要问题

### 2.1 MST 优化的目标与最终目标不一致

现有第一阶段实际优化的是某棵树的边权总和：

\[
\min_T\sum_{(i,j)\in T}w_{ij}.
\]

但整个问题最终优化的是各仓库协同配送路线成本之和：

\[
\min_{\{C_p\}_{p\in D}}
\sum_{p\in D}F_p(C_p),
\]

其中：

- \(C_p\) 是分给仓库 \(p\) 的客户集合；
- \(F_p(C_p)\) 是第二、三阶段得到的卡车—无人机联合路线成本。

树连接代价小，并不意味着这些客户组成一条巡回路线后的成本小。典型情况是：

- MST 可以通过一条很短的边把一个远离仓库的客户链连接起来；
- 但卡车路线必须从仓库出发并最终返回仓库；
- 无人机同步等待、航程限制和多无人机并发也没有被 MST 目标直接反映。

在对称度量 TSP 中，MST 至少是路线成本的下界；但这里是有向道路网络、集合距离和同步配送问题，这种联系已经明显减弱。

### 2.2 当前方法只在“一棵已经选定的 MST”上寻找分区

现有实现首先生成唯一的全局 MST，然后在这棵树上决定每个客户连接哪个仓库。

这意味着即使完全图中存在一条非常适合某个分区的非 MST 边，后续树形动态规划也无法使用它。

换句话说，它解决的是：

\[
\text{在固定 MST 上寻找较优分区},
\]

而不是：

\[
\text{在完整候选边集合上寻找最优多仓库森林或最优路线分区}.
\]

因此，它可能受到前面那一次 MST 决策的强烈限制。

### 2.3 分组不平衡会拖慢第二阶段

论文中的消融结果表明，MST 分区通常比 NN 分区更不平衡，而最大客户组过大会显著增加后续 Set-TSP 的计算时间。Set-MST + Set-TSP 往往能得到较好的路线成本，但计算时间也明显更高。

这不是单纯的实现问题，而是 MST 的目标决定的：

- MST 只关注边权总和；
- 它没有客户数量、候选集合规模或后续 MILP 规模约束；
- 因此可能形成一个很大的主分支和若干很小的分支。

需要注意：原问题的目标是各路线成本之和，并不是 makespan，因此不能为了“看起来平均”而强制完全均分。合理做法应是**软限制超大客户组**，而不是硬性要求每个仓库客户数相同。

### 2.4 有向路网与 `nx.Graph` 存在结构性不一致

论文将道路网络定义为强连通有向图，卡车从 \(u\) 到 \(v\) 的最短路不一定等于从 \(v\) 到 \(u\) 的最短路。

但原实现的 `set_mst()` 使用：

```python
graph = nx.Graph()
```

随后又遍历有序客户对：

```python
for city in self.cities:
    for _city in self.cities:
        graph.add_edge(city, _city, weight=weight)
```

对于无向图，同一对节点 \((i,j)\) 和 \((j,i)\) 对应的是同一条边。当

\[
d^{set}_{ij}\neq d^{set}_{ji}
\]

时，后加入方向的边权会覆盖先加入方向的边权。

而 H2H 接口本身支持的是有向 `source -> target` 距离查询，因此这一不一致在 H2H 版本中仍然存在。

这应当是第一项修正。不过不能简单把 `nx.Graph` 换成 `nx.DiGraph`，因为普通 MST 并不直接适用于有向图；有向最小树形图也仍然不能很好地表示闭合配送路线。

## 三、可替代 MST 的方法比较

| 方法 | 与最终路线目标的匹配程度 | 计算开销 | 实现难度 | 建议用途 |
|---|---:|---:|---:|---|
| 多仓库根生成森林 MSF | 较低 | 低 | 低 | 修正后的直接基线 |
| 平衡广义指派 / 最小费用流 | 中等偏低 | 很低 | 低 | 效率和分组平衡基线 |
| Route-first, cluster-second | 中等 | 中等 | 中等 | 路线感知的确定性基线 |
| MST/MSF + relocate/swap 局部搜索 | 高 | 中等 | 中等 | **当前最推荐** |
| 解码器引导 ALNS | 很高 | 可按时间控制 | 较高 | **论文主要创新候选** |
| 多仓库 Generalized TSP 联合 MILP | 最高 | 很高 | 很高 | 小规模最优参考 |

## 四、第一步：用多仓库根生成森林替换当前 MST 划分

这是最容易实现、也最适合先做消融实验的方法。

### 4.1 先构造完整的有向集合转移代价

统一为所有仓库和客户构造候选集合：

\[
S_p=\{p\},\qquad p\in D,
\]

客户仍使用论文中的边界候选集合 \(S_c\)。

然后计算：

\[
A_{ij}=d^{set}(S_i,S_j),
\qquad i,j\in D\cup C.
\]

这里必须同时保存：

\[
A_{ij},\quad A_{ji},
\]

而不是直接放进无向图。

为了生成森林，可以显式对称化：

\[
W_{ij}^{\mathrm{avg}}
=
\frac{A_{ij}+A_{ji}}{2},
\]

或者：

\[
W_{ij}^{\mathrm{sum}}
=
A_{ij}+A_{ji}.
\]

对于闭合配送路线，更建议使用 `sum` 或 `average`，而不是仅保留某一个方向。还可以把

\[
W_{ij}^{\max}=\max(A_{ij},A_{ji})
\]

作为鲁棒性消融版本。

### 4.2 加入超级根节点

增加一个超级根节点 \(r\)，并连接所有仓库：

\[
W_{r,p}=0,\qquad p\in D.
\]

在扩展图上计算一次 MST，然后删除超级根及其边。得到的就是以各仓库为根的生成森林。

只要禁止仓库之间的直接连接，或者确保超级根—仓库零权边全部保留，删除超级根后，每个连通分量就会对应一个仓库。

这个方法相比原 `mst_partition()` 的优点是：

- 原方法先固定一棵普通 MST，再在这棵树上分组；
- 超级根方法直接在完整边集合上求一个多根生成森林；
- 对于选定的对称森林代价，它具有更清晰的全局最优含义；
- 实现改动较小，可作为 `Set-MSF` 新基线。

但它仍然只优化树代价，因此不建议将其作为最终主要方法。

## 五、最推荐的方法：解码器引导的分区局部搜索

可以将第一阶段重新定义为一个带昂贵评价函数的集合划分问题。

设当前分区为：

\[
\Pi=\{C_p:p\in D\}.
\]

对仓库 \(p\) 的客户集合 \(C_p\)，使用现有第二、三阶段计算：

\[
F_p(C_p).
\]

对于把客户 \(c\) 从仓库 \(p\) 移动到仓库 \(q\)，真实增量为：

\[
\Delta(c:p\rightarrow q)
=
F_p(C_p\setminus\{c\})
+
F_q(C_q\cup\{c\})
-
F_p(C_p)
-
F_q(C_q).
\]

一个移动只影响两个仓库，因此不需要重新计算所有路线。这是当前三阶段框架非常适合局部搜索的原因。

问题在于：如果对每个候选移动都重新运行 Gurobi Set-TSP 和动态规划，代价过高。因此应使用两级评价。

### 5.1 第一级：快速有向路线代理

对每个仓库维护一条当前访问顺序：

\[
R_p=(p,c_1,c_2,\ldots,c_k,p).
\]

使用前面构造的有向集合转移矩阵 \(A\)，定义快速代理成本：

\[
\widehat F_p(R_p)
=
A_{p,c_1}
+
\sum_{i=1}^{k-1}A_{c_i,c_{i+1}}
+
A_{c_k,p}.
\]

把客户 \(c\) 插入当前弧 \((u,v)\) 的增量为：

\[
\Delta_{\mathrm{insert}}(c;u,v)
=
A_{u,c}+A_{c,v}-A_{u,v}.
\]

从前驱 \(i\)、后继 \(j\) 之间删除客户 \(c\) 的增量为：

\[
\Delta_{\mathrm{remove}}(c;i,j)
=
A_{i,j}-A_{i,c}-A_{c,j}.
\]

因此，一次 relocate 操作的近似增量可以在线性时间内得到，不需要重新求解 Set-TSP。

可以使用以下邻域：

- `relocate(1,0)`：一个客户换仓库；
- `swap(1,1)`：两个仓库交换一个客户；
- `relocate(2,0)`：相邻客户链整体移动；
- `swap(2,1)`：两个客户与一个客户交换；
- ejection chain：连续执行多个跨仓库移动。

### 5.2 第二级：只精确评价少量候选移动

每轮先用快速代理评价全部移动，只保留最有希望的前 \(B\) 个，例如 \(B=5\) 或 \(10\)。

然后对这些候选调用现有：

- `get_seq()`；
- `local_search_multi_drone_appr()`；

仅重新计算受影响的两个仓库，得到真实或高保真的 \(\Delta\)。

这样形成：

\[
\text{大量廉价筛选}
\quad+\quad
\text{少量下游精确评价}.
\]

H2H 后端非常适合这种方式：第一阶段会频繁查询有向道路距离，而 H2H 可以避免重新运行 Dijkstra。但需要注意，H2H 只能减少最短路查询开销，不能消除大量重复 Set-TSP MILP 求解，因此“代理筛选”仍然必要。

### 5.3 对过大客户组加入软惩罚

为了避免 MST 中出现的极端不平衡，可以定义：

\[
U=\left\lceil\frac{|C|}{|D|}\right\rceil+\delta,
\]

并加入：

\[
P(\Pi)
=
\rho\sum_{p\in D}
\left[\max(0,|C_p|-U)\right]^2.
\]

搜索代理目标为：

\[
\widehat J(\Pi)
=
\sum_{p\in D}\widehat F_p(C_p)
+
P(\Pi).
\]

其中：

- \(\delta\) 控制允许的不平衡范围；
- \(\rho\) 控制对超大客户组的惩罚。

这不是原问题的业务目标，而是一个**计算复杂度正则项**。因此实验中必须同时报告：

- \(\rho=0\)：只优化配送成本；
- \(\rho>0\)：成本—计算时间折中；
- 不同 \(\rho\) 下的 Pareto 曲线。

不要直接规定每个仓库必须分配完全相同数量的客户，否则可能强行破坏道路网络的自然空间结构。

## 六、进一步升级：解码器引导 ALNS

在局部搜索稳定后，可以把它扩展成 ALNS。

ALNS 的基本过程是：

\[
\text{destroy}
\rightarrow
\text{repair}
\rightarrow
\text{accept/reject}.
\]

适合当前问题的破坏算子包括：

- **随机移除**：随机选择若干客户；
- **最差客户移除**：移除当前边际成本最高的客户；
- **相关客户移除**：移除集合距离接近的一组客户；
- **边界客户移除**：移除对两个仓库归属差异很小的客户；
- **过载仓库移除**：优先从最大客户组中移除；
- **无人机不友好客户移除**：移除导致同步等待或航程受限较严重的客户。

修复算子包括：

- 最小插入代价；
- regret-2；
- regret-3；
- 带客户组规模惩罚的插入；
- 使用下游解码器估计的插入。

接受准则可以使用模拟退火，从而允许短期接受较差解，避免被局部最优困住。

这个方向的研究价值高于“把 MST 换成另一种聚类”：

> 它直接优化分组对第二、三阶段的影响，并将客户归属与访问顺序联合考虑。

## 七、其他值得作为对比基线的方法

### 7.1 平衡广义指派 / 最小费用流

为每个仓库—客户对定义单客户指派代价：

\[
g_{pc}=A_{p,c}+A_{c,p},
\]

然后求解：

\[
\min\sum_{p\in D}\sum_{c\in C}g_{pc}x_{pc},
\]

满足：

\[
\sum_p x_{pc}=1,
\]

并为每个仓库加入软容量或上下界。

优点：

- 计算速度快；
- 可直接控制客户组规模；
- 易于形成确定性基线。

缺点：

- 主要根据仓库—客户关系分配；
- 没有充分考虑同一组客户之间的路线协同关系。

因此，适合作为效率基线，不适合作为最终主要算法。

### 7.2 Route-first, cluster-second

先在所有客户上生成一条集合化“巨型路线”，然后沿该路线切分成多个连续片段，并为每个片段选择仓库。

设巨型顺序为：

\[
(c_1,c_2,\ldots,c_n).
\]

仓库 \(p\) 服务区间 \([i,j]\) 的代理成本为：

\[
Q(p,i,j)
=
A_{p,c_i}
+
\sum_{t=i}^{j-1}A_{c_t,c_{t+1}}
+
A_{c_j,p}.
\]

然后使用动态规划选择切分位置和仓库。

它比 MST 更路线感知，但有一个明显限制：同一仓库的客户必须在巨型路线中形成连续片段。它适合作为确定性强的基线，但一般不如后续局部搜索或 ALNS 灵活。

## 八、建议的代码改造结构

目前的 `set_mst()` 同时承担：

- 集合边权计算；
- 图构造；
- 客户分区。

建议拆成四层。

### 8.1 有向集合代价构造

```python
def build_directed_set_costs(self, convex_sets):
    """返回 A[u][v]，严格保留有向集合转移代价。"""
```

### 8.2 多仓库生成森林分区

```python
def partition_rooted_msf(self, directed_costs):
    """对称化后构造超级根多仓库生成森林。"""
```

### 8.3 快速路线代理

```python
def estimate_group_route(self, depot, cities, directed_costs):
    """使用 cheapest insertion 和局部搜索生成快速路线代理。"""
```

### 8.4 纯函数式仓库组评价

```python
def evaluate_group(self, depot, cities, exact=False):
    """评价单个仓库组，不修改 self.groups、self.solution 或 self.cost。"""
```

当前 `single_solution()` 会直接累加 `self.cost`，不适合在局部搜索中反复试算。

需要将评价与最终结果提交分开，例如：

```python
cost, seq, solution = evaluate_group(...)
```

只有最终接受分区后再写入：

```python
self.groups
self.solution
self.cost
```

同时增加缓存：

```python
cache_key = (depot, frozenset(cities))

group_cache[cache_key] = {
    "approx_cost": ...,
    "exact_cost": ...,
    "seq": ...,
}
```

因为 relocate 和 swap 搜索过程中，同一个客户集合可能重复出现。

## 九、实验设计

建议至少比较以下方法：

1. 原始 Set-MST；
2. 修正有向代价后的 Set-MST；
3. 超级根 Set-MSF；
4. 平衡广义指派；
5. Set-MSF + relocate；
6. Set-MSF + relocate + swap；
7. 解码器引导 ALNS。

核心指标包括：

- 最终第三阶段目标函数值；
- 第一阶段时间；
- 第二阶段时间；
- 第三阶段时间；
- 总时间；
- 最大客户组规模；
- 客户组规模标准差；
- H2H 查询次数；
- 精确下游评价次数；
- 相同时间预算下的最好结果；
- 相对于原 Set-MST 的实例胜率。

消融实验应包括：

- `average`、`sum`、`max` 三种有向代价对称化方式；
- 是否加入超大客户组惩罚；
- 仅 relocate 与 relocate + swap；
- 代理评价与代理 + 精确重评价；
- 每轮精确评价候选数量 \(B\)；
- 不同 ALNS destroy/repair 算子；
- 不同时间预算。

在小规模实例上，可以建立一个集成多仓库 Set-TSP/MILP，得到最优解或较强下界，用于判断各分区方法的真实差距。大规模实例则应采用相同 wall-clock 时间预算，并使用相同实例、随机种子进行配对比较。

## 十、最终建议

### 10.1 第一阶段：先做正确性修正

- 统一计算有向 \(A_{ij}\)；
- 不再让有向代价直接写入 `nx.Graph`；
- 实现超级根 Set-MSF；
- 与原 Set-MST 做结果一致性和分组差异实验。

### 10.2 第二阶段：实现主要实用改进

- Set-MSF 初始化；
- 有向 cheapest insertion 路线代理；
- relocate + swap；
- 仅对前 \(B\) 个候选调用现有第二、三阶段；
- 加入客户组结果缓存。

这一版本最可能在有限开发成本下同时取得：

- 更低的最终路线成本；
- 更合理的客户组规模；
- 更短的 Set-TSP 时间。

### 10.3 第三阶段：形成论文创新

将上述局部搜索扩展为：

> **H2H-supported Decoder-Guided ALNS for Joint Depot Assignment and Customer Sequencing**

核心创新点不是“用 ALNS 替代 MST”，而是：

1. 保留有向集合服务代价；
2. 联合调整客户归属和访问顺序；
3. 使用现有卡车—多无人机动态规划解码器评价分区；
4. 使用代理筛选与 H2H 查询降低重复评价成本；
5. 显式控制大客户组导致的第二阶段计算爆炸。

这是比单独替换 MST 更完整、也更容易形成学术贡献的路线。
