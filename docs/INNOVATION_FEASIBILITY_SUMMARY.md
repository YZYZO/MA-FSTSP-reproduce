# MA-FSTSP 创新方向可行性摘要

## 1. 当前算法与研究基础

论文算法分为三阶段：

1. Phase 1：用 Set-MST 将客户分配给不同仓库/卡车。
2. Phase 2：每个分组独立求 Set-TSP 客户访问顺序。
3. Phase 3：在固定访问顺序下，用动态规划联合规划卡车和多架无人机。

当前分支新增的 H2H 只负责按需查询卡车最短路，没有改变上述优化逻辑。它适合支撑更多候选分配和局部调整，但 Set-TSP 与 Phase 3 状态搜索仍可能是主要耗时来源。

论文目标是**所有卡车组完工时间之和**，不是最大完工时间。因此，“负载均衡”如果定义不清，可能降低最大完工时间，却提高原论文目标值。

## 2. 各创新方向的判断

### 2.1 负载均衡

可行，但不能只均衡客户数量。客户工作量还取决于道路结构、无人机适用性、候选边界点数量和路线位置。

建议区分：

- 运营负载：每辆车预计的最终路线时间。
- 计算负载：该组 Set-TSP 和 Phase 3 的预计状态空间。

更安全的目标是：先保证总成本不明显劣于原始 SMST，再降低最大运营负载或计算负载。当前本地实例已出现 `12/6/2/0/0`、`7/5/4/2/1/1/0/0/0/0` 等不均衡分组，说明该方向有现实基础。

### 2.2 聚类与社区发现

聚类和社区发现不应混为一谈：

- K-Means/K-Medoids 等聚类可以固定簇数为车辆数，但普通欧氏距离不适合道路网络。
- 社区发现根据图结构自动决定社区数，更容易识别河流、桥梁和道路瓶颈，但社区数通常不等于车辆数。
- 当前 MST 天然以仓库为锚点，但允许空组，也不保证负载均衡。

社区数与车辆数不一致不是不可解决：社区多于车辆时可进行“社区到车辆”的多对一指派；社区少于车辆时可拆分大社区或允许空车。建议在“客户+仓库”的 set-distance 相似图上做仓库锚定社区发现，不要直接在完整道路图上发现社区。

需要注意：当前 `set_mst` 使用无向图，但底层道路距离可能有方向性。后续比较前应明确如何对称化 set-distance，避免结果受边权覆盖顺序影响。

### 2.3 零散客户

建议先识别主体簇/社区，将噪声客户留到第二步分配。两种策略中，优先考虑“加入哪辆车使路线增量最小”，而不是只选择当前客户数最少的车辆。

增量估计应同时比较：

- 插入卡车路线的增量；
- 由无人机服务时的同步时间增量；
- 加入后对车辆负载上限的影响。

### 2.4 先选择两个无人机高收益客户

简单选择两个单点收益最高的客户，容易忽略发射点、回收点、航程和两架无人机之间的协同关系。当前 Set-TSP 本身已经具有单客户无人机感知，因此单点打分的创新性有限。

更合理的方案是计算**客户对的协同收益**：比较卡车服务两个客户的成本，与两架无人机同步服务两个客户的成本。然后用软约束或候选顺序，引导 Set-TSP 将高收益客户对安排为相邻客户块，最终仍用 Phase 3 真实成本选择方案。

不建议硬性锁定客户对；应始终保留原算法解作为候选，避免代理评分错误导致负收益。该方法还应推广到大小不超过无人机数 `k` 的客户块，避免固定为“2”缺乏一般性。

### 2.5 动态客户分配与为什么使用 MST

MST 的优势是计算快、能生成每个分量包含一个仓库的结构，在原始欧氏 MDTSP 中还有近似保证。论文实验也表明 MST/SMST 的最终成本优于 NN 类方法。

但 MST 优化的是树边权，不是最终 Set-TSP+无人机同步成本；相关近似保证不能直接推广到非对称 set-distance 的 MA-FSTSP。因此最推荐的方案不是删除 MST，而是：

1. 用 SMST 生成初始分组。
2. 选择分区边界客户、离群客户和高负载组客户。
3. 尝试单客户迁移、客户交换或小社区整体迁移。
4. 用便宜的路线增量筛选动作。
5. 只重新求解受影响的两个卡车组，真实总成本改善才接受。

独立小测试已证明：在一个零无人机特例中，MST 后移动一个客户可使总精确 TSP 成本下降 7.22%，最大单车路线下降 15.61%。这只证明存在改进空间，不代表真实数据集平均收益。

## 3. 推荐的论文主线与优先级

建议将这些想法组织成两条主线：

1. **负载与路线感知的动态客户分配**：SMST 初始化，结合社区/聚类、零散点插入和跨组局部调整。优先级最高。
2. **多无人机客户块感知的访问顺序规划**：提前识别高协同收益客户对/客户块，引导 Phase 2 顺序。优先级次高。

聚类和社区发现更适合作为 Phase 1 的初始化方法与消融对比，不建议单独作为主要贡献。

## 4. 建议实验指标

- 原论文总成本。
- 最大单车完工时间。
- 各组客户数、路线时间和计算负载的离散程度。
- 空闲车辆数量。
- Phase 1/2/3 分阶段耗时和总耗时。
- 动态调整次数、接受率及每次调整的真实收益。
- 原始 SMST、聚类、社区、动态调整、客户块引导的配对消融实验。

## 5. 尚需确认的问题

1. “负载均衡”指客户数、路线时间、最大完工时间，还是求解耗时？
2. 是否要求每辆卡车至少服务一个客户？原论文与当前代码允许空车。
3. “两个高收益点”是全局、每辆车，还是每次同步投放的两个客户？
4. 是否允许改变原论文的总成本目标，加入最大完工时间或公平性目标？
