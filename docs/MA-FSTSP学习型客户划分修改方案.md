# MA-FSTSP 学习型客户划分修改方案

> 研究方向：用“求解器感知的层次化强化学习”改进第一阶段客户划分，使其提前考虑第二阶段 Set-TSP 的求解难度和第三阶段配送成本。

## 1. 问题与目标

原论文采用三阶段流程：

1. Set-MST 完成客户划分；
2. Set-TSP 求解各客户组的访问顺序；
3. 在固定顺序上分配车辆与无人机任务。

目前第一阶段主要依据集合距离，没有控制各组的下游计算难度。即使客户数量相近，不同客户的候选道路节点数量也可能相差很大，导致某些 Set-TSP 模型过大、运行时间过长，甚至超时；划分结果还会继续影响第三阶段最终成本。

因此，目标不是简单地让各组客户数相等，而是：

- 降低第二阶段的长尾运行时间和超时率；
- 保持或改善第三阶段最终配送成本；
- 让学习策略本身的计算开销足够小。

## 2. 推荐方案

采用以下流程：

```text
Set-MST 初始划分
        ↓
上层策略：选择需要调整的两个客户组
        ↓
下层策略：relocate / swap / stop
        ↓
代理模型：预测成本、运行时间和超时风险
        ↓
得到最终划分，再执行原有 Set-TSP 和第三阶段算法
```

第一版不从零生成完整划分，也不替换原求解器。它只在 Set-MST 结果上做少量局部修改，训练难度和数据成本相对可控。

### 策略分工

- **上层策略**：选择最值得调整的仓库/客户组对，或选择停止。
- **下层策略**：优先实现客户移动 `relocate`，稳定后再加入客户交换 `swap`。
- **代理模型**：分别预测第三阶段最终成本、第二阶段对数运行时间、超时概率和预测不确定性。

训练时大多数动作由代理模型快速评分，只对高价值或高不确定样本调用真实 Set-TSP 和第三阶段算法。

## 3. 模型需要的主要特征

- **客户特征**：坐标、到各仓库的有向道路距离、无人机距离、候选道路节点数量、最近与次近仓库。
- **客户组特征**：客户数、候选节点总量、候选节点平方和、MST 长度、几何紧凑度、边界连接代价。
- **求解器特征**：短时间试求得到的 LP 松弛、初始解、节点数、最优间隙，以及历史超时标签。

可先使用下面的 Set-TSP 规模代理：

$$
V_k=(n_k+1)^2+\sum_i s_i^2+\left(\sum_i s_i\right)^2,
$$

其中 $n_k$ 是客户组规模，$s_i$ 是客户 $i$ 的候选道路节点数量。

优化时以第三阶段最终总成本为主目标，把第二阶段运行时间和超时风险作为约束或惩罚。当前程序按仓库串行求解，因此先优化 $\sum_k T_k$；以后若改为并行，再考虑 $\max_k T_k$。

## 4. 实施顺序

1. **稳定原始基线**  
   保留官方 Set-MST 作为对照；修复有向道路距离在无向 MST 中可能因客户顺序而被覆盖的问题。学习版默认使用双向距离均值，并对 `min/max` 做消融实验。

2. **增加求解器遥测和缓存**  
   为 Set-TSP 设置统一时间上限，记录 `Status`、`Runtime`、`NodeCount`、`MIPGap`、`ObjBound` 和 `SolCount`；按地图、参数、仓库和客户集合缓存结果。

3. **生成训练数据**  
   从 MST 划分及其 `relocate/swap` 扰动中采样，保存最终成本、对数运行时间和超时标签。必须按原始实例划分训练集、验证集和测试集，避免数据泄漏。

4. **先训练代理模型**  
   检查它能否正确排序不同划分的优劣，并识别高超时风险。代理模型可靠后再进入强化学习。

5. **训练层次化策略**  
   先在小规模实例上用一步局部搜索结果做模仿预训练，再训练上层选组、下层调客户的策略；定期用真实求解结果更新代理模型。

6. **接入并评估**  
   将学习策略作为新的第一阶段选项接入原三阶段程序，并完成基线对比和消融实验。

## 5. 实验与验收

对比方法包括：官方 Set-MST、Set-NN、容量均衡 MST、使用同一代理指标的非学习贪心、单层强化学习和层次化强化学习。

主要指标包括：

- 最终配送成本；
- 第二、第三阶段及端到端时间的中位数、P90、最大值；
- 超时率、最大客户组规模和 $V_k$；
- 学习策略耗时及真实求解器调用次数。

初步验收标准是：第二阶段 P90 时间和超时率明显下降，最终成本不劣于原 Set-MST，并能在未见过的路网上保持效果。建议先用 Manhattan 1K 训练和验证，再用 11K、55K 测试跨规模泛化。

## 6. 开发准备

当前本机检测到的 Python 环境为：

```text
D:\Anaconda3\envs\MA-FSTSP\python.exe
```

已有 PyTorch（CPU）和 Gurobi 10.0.1。第一版建议安装：

```bash
pip install scikit-learn gymnasium tensorboard
```

第一版暂不需要 PyTorch Geometric、Stable-Baselines3 或 GPU。

建议新增 `src/learning/`，用于放置特征、单组评估器、缓存、代理模型、强化学习环境和层次策略；同时为遥测、特征、缓存、环境及有向 MST 不变性分别编写新的测试文件。

## 7. 下一步

先完成 **“有向 MST 修正 + Set-TSP 遥测与缓存”**。没有稳定、可复用的真实标签之前，不开始强化学习训练。

开始编码前还需要确定：

1. 最终目标继续使用各仓库成本之和，还是改为最大仓库完成时间；默认保留成本之和。
2. 每个客户组的 Set-TSP 时间预算如何随实例规模设置。
3. 是否接受双向道路距离均值作为学习版默认对称化方法。
